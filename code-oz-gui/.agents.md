# Codex execution contract for code-oz-gui

You (Codex) are executing against a written design brief authored by Claude. Read it before touching any code:

**Required reading order:**

1. `docs/CLAUDE_DESIGN_BRIEF.md` — the v0 design brief. **This is the source of truth.**
2. `~/Projects/code-oz/CLAUDE.md` — the 23 non-negotiable rules of the CLI this GUI is a client of.
3. `~/Projects/code-oz/src/state/schemas.ts` — authoritative event-type and phase definitions.

## Operating rules

- **Brief overrides instincts.** If your default styling, naming, or architecture would deviate from the brief, follow the brief.
- **One commit per execution step.** §18 of the brief lists 10 steps. Don't skip; don't bundle unless told.
- **Vocabulary is a hard contract.** §4 of the brief has a swap table. Apply it everywhere. Grep for banned terms after every commit.
- **No fake data outside `fixtures/`.** All UI state must derive from real events or from the fixture run in `fixtures/sample-run/`.
- **No `setTimeout`-based theatre.** Real SSE, real file watches, real subprocess spawns.
- **TypeScript strict.** No `any`. Prefer discriminated unions for event types.
- **Tailwind v4** is in use. CSS variables live in `app/globals.css`.
- **Server-side fs access only.** Browser never touches the filesystem.
- **Localhost only.** Bind 127.0.0.1; document this.

## After each commit

Write a 2-line commit message: imperative subject + one-sentence why. Then stop and wait for Claude's review verdict. Verdicts are:

- `proceed` — go to next step in §18.
- `revise: <items>` — fix listed items, then proceed.
- `escalate: <question>` — Claude reconsiders the brief.

## Reference repos

- `~/Projects/code-oz/` — the CLI this GUI controls. Read-only for you; consult freely.
- `~/Projects/code-oz/src/state/schemas.ts` — event types.
- `~/Projects/code-oz/src/artifacts/` — artifact validators (source of truth for AUDIT.md / SPEC.md / PLAN.md / etc. shapes).
- `~/Projects/code-oz/docs/design/SESSION_M17_KICKOFF.md` — AUDIT phase contract.

## Forbidden

- Inventing event types not in `schemas.ts`.
- Inventing artifact field names not in `src/artifacts/`.
- Adding emoji to UI strings (single Unicode bullet `●` allowed; nothing else).
- Marketing copy or "welcome" microcopy.
- Adding new dependencies without justification in the commit message.
