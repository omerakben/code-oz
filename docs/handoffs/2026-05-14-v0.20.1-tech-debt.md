## Lessons for v0.20.2 + future releases

1. **Cross-model review converges in 4-6 rounds for a release of this scope.** Plan for it. The first 2 rounds catch most of the load-bearing issues; rounds 3-6 catch progressively smaller drift; round 6 typically catches the last public-facing item (in this release: the broken doc path).

2. **Frozen-in-time historical records are valuable.** Don't retroactively rewrite design docs / planning docs / Codex response files to match the final state. They are records of how the release happened. Add status headers ("archived / shipped on date X") instead.

3. **Public-facing drift is the only release-blocking class.** Internal-doc drift (TD-1, TD-4 above) is real but does not mislead end users. Catch it; capture it; ship without it.

4. **Run the fresh-clone smoke EARLY.** It caught the GUI-sub-project deps issue and the "AI software company in README hero" issue before Codex did. Adding it to the standard release prep cadence at v0.20.2+ would let Codex focus on framing and substance instead of mechanical drift.
