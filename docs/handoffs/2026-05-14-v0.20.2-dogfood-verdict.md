## The dogfood EXPOSED a separate runtime bug (out of v0.20.2 scope)

BUILD attempt 2 fired correctly with the carry-forward prepared (carry-forward mechanism worked), but **the patch failed to apply** because the worktree still had attempt 1's files:

```
error: .gitignore: already exists in working directory
error: package.json: already exists in working directory
error: src/prdiff.ts: already exists in working directory
error: tsconfig.json: already exists in working directory
```

Root cause: between BUILD attempt N and attempt N+1, the orchestrator does NOT reset the worktree to the base commit. Attempt 2 emits a patch with `change: 'added'` for the same paths attempt 1 already created. `git apply --check` correctly refuses.

This is a **separate v0.20.3 finding**, not a v0.20.2 regression. It affects any BUILD with multiple attempts on a scaffold task. The fix lives in `src/phases/build.ts` restart-on-fail logic — likely needs a `worktree_reset_to_base` step before each `build_started` event for `attempt > 1`.

The events.jsonl evidence is preserved at `~/Projects/prdiff/.code-oz/state/runs/01KRM4EBQRX0GK1RT85RP1EF6D/events.jsonl` for the v0.20.3 fix to reference.
